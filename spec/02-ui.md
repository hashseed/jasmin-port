## 1. Application shell

```
+--------------------------------------------------------------------------------+
| File  Edit  Run                                                    (menu bar)  |
| [new][open][save] | [undo][redo] | [cut][copy][paste] | [back][fwd] |          |
|   [run/pause][step][exec line][stop] | [reset] | [take snap][load snap]        |
+--------------------------------------------------------------------------------+
| Welcome | new program  | prog.asm |                               (tab strip)  |
+--------------------------------------------------------------------------------+
|                                                                                |
|                 selected tab: a Help page (02 §12) or a Document (02 §5)       |
|                                                                                |
+--------------------------------------------------------------------------------+
| (status label, dark red, effectively unused)                                   |
+--------------------------------------------------------------------------------+
```

- Window title `Jasmin`; becomes `Jasmin - <document title>` when a document tab is
  selected (it is not reset when a help tab is selected afterwards).
- The window starts maximized. *Port note:* the app fills the browser viewport
  (`100vw x 100vh`), minimum layout size 800x600 with scrolling below that. Narrower
  than 800 px (phones), there is no minimum: help pages use the full width, the
  toolbar scrolls sideways, and document tabs stack their sections (§5).
- On startup a **Welcome** help tab is opened and selected. No document is open.
- Tab strip: one tab per open document or help page, in opening order. Newly
  added tabs are appended and selected. Right-clicking the tab strip opens a context
  menu with one item, **Close Tab**, which closes the *currently selected* tab.
  *Port note:* double-clicking a document tab's title (or F2 on a focused document
  tab) renames it inline: Enter or leaving the field commits the trimmed name, Escape
  or an empty name keeps the old one. The window title follows, and Save suggests
  `<title>.asm` while the document has no file. Help tabs cannot be renamed.
- Closing a tab never prompts, even with unsaved edits. *Port note:* add a
  `beforeunload` warning when any document has unsaved changes (only addition).
- The bottom status label (color `rgb(204,0,51)`) exists in the frame but the documents
  write errors to their own label (02 §6.4). The port may omit it.

## 4. Enablement rules (`MainFrame.checkButtonStates`)

Re-evaluated after every action, tab change, caret move and undoable edit.

**A document tab is selected and not running:**
- Enabled: Save (button and menu), Save Memory, Paste (button and menu), Edit menu,
  Run menu, Close Document, Run, Step, Execute current line, Stop, Reset, Take Snapshot,
  the editor.
- Load Snapshot: enabled only if this document has a snapshot.
- Undo / Redo (button and menu): per the document's undo stack.
- Cut / Copy (button and menu): only when the editor has a non-empty selection.
- Run menu item enabled, Pause menu item disabled.
- Back / Forward: disabled.

**No document selected (a help tab, or nothing):** everything above disabled. Back and
Forward reflect the selected help tab's history.

**A document is running:** everything above disabled, except: the Run/Pause button
(shows the pause icon and pauses) and Reset. The editor is read-only. Note the
original also disables the Stop button and the Pause *menu item* while running
(07, Q-UI-1); the port enables Stop and Pause while running.

Always enabled: New, Open Code, Load Memory (menu), Configuration, Exit.

## 5. Document view layout

*Port note:* narrower than 800 px, a document tab has no split panes. Its sections
stack in one scrolling column: editor (60% of the viewport height, at least 280 px),
Registers with Flags, Memory (420 px), FPU Registers, and the bottom tabs (380 px).
Divider positions are kept for the wide layout.

A document tab is a set of nested split panes (3 px dividers, continuous layout):

```
+-------------------------+-----------------------------------------+---------------------+
| Registers  (titled box) |  editor: gutter | code text             | Memory (titled box) |
| [bin][±dec][dec][hex]   |                                         | [desc][hex][highlight] [8 Bit][16Bit][32Bit]
| > EAX: 0                |                                         | address | signed int | unsigned int | hex
| > EBX: 0                |                                         | 0x0     | 0          | 0            | 0x00000000
|   ... ECX EDX ESI EDI   |                                         | 0x4     | ...
|   ... ESP EBP EIP       |-----------------------------------------|                     |
| [ ]Carry   [ ]Overflow  | error message line (red)                |                     |
| [ ]Sign    [ ]Zero      |-----------------------------------------|                     |
| [ ]Parity  [ ]Auxiliary | Help      | context help HTML           |                     |
| [ ]Trap    [ ]Direction | 7-Segment | / device canvas             |                     |
|-------------------------| StripLight|                             |                     |
| FPU Registers           | Console   |                             |                     |
| name | value            | Graphics  |                             |                     |
+-------------------------+-----------+-----------------------------+---------------------+
```

- Outer horizontal split (`split2`): left column (Registers over FPU) | rest. Default
  divider 300 px.
- Left column vertical split (`split3`): Registers (top) | FPU Registers (bottom).
- Rest horizontal split (`split1`): center column | Memory. Default: memory panel about
  350 px wide (divider at window width - 350 - split2).
- Center vertical split (`split4`): editor (top) | bottom tab pane. Default divider at
  window height - 350.
- The bottom tab pane has its tabs on the **left** edge, in this order: `Help`,
  `7-Segment`, `StripLight`, `Console`, `Graphics`.
- Divider positions are persisted as settings `split1.location` ... `split4.location`
  and reused for every new document (09 §3).

## 6. Editor

### 6.1 Text area
- Plain text, styled by the highlighter (6.3). Font family and size from settings
  (`font`, default `Sans Serif`; `font.size`, default 12). *Port note:* map Java's
  logical fonts: `Sans Serif` -> `sans-serif`, `Monospaced` -> `monospace`. The
  port's default is the bundled `JetBrains Mono` (09 §3).
- **Auto-indent:** typing Enter copies the leading spaces/tabs of the current line
  (up to the caret column) onto the new line.
- Undo/redo history up to 99,999 edits; style changes are not undo steps.
- Right-click context menu: Undo, Redo, *separator*, Cut, Copy, Paste. Cut/Copy need a
  selection; all items disabled while running; Undo/Redo per stack.
- Read-only while the program runs.
- *Port note:* CodeMirror 6 is the recommended editor (gutter, decorations, undo,
  keymaps). Line breaks are `\n`; strip `\r` when opening files.

### 6.2 Gutter (line numbers)
- One row per line, starting at **0** (the line index equals the EIP value for that
  line). Number right-aligned in the editor font.
- A 10x10 breakpoint area left of the number shows `breakpoint.png` when set.
- **Left-click** a row: toggle the breakpoint for that line index.
- **Right-click** a row: set `EIP := line index` and refresh all panels.
- **Execution mark:** the row whose index equals EIP gets a bright green
  (`rgb(0,255,0)`) background. After Step / Run end / Stop / Execute-current-line the
  editor scrolls so the marked row is visible.
- The original pre-creates gutter rows to fill the visible height, so rows exist (and
  can hold breakpoints / the mark) beyond the last text line.
- Breakpoints belong to line *indices* in the original and do not move when lines are
  inserted above (07, Q-UI-2: port moves them with the text).

### 6.3 Syntax highlighting
Applied per line from that line's parse result (03). All matching is
case-insensitive and on whole tokens (bounded by start/end or any delimiter from
`[ ] + - * : . tab , ; ' space`).

| Element | Color | Style |
|---|---|---|
| default text | black | plain |
| mnemonic (every whole-token occurrence of the line's mnemonic) | `rgb(0,0,144)` | bold |
| register names `EAX AX AL AH EBX ... EBP BP EIP` (every whole-token occurrence) | `rgb(0,144,40)` | bold |
| label (jump target) | `rgb(255,144,0)` | bold |
| constant (`EQU` label) | `rgb(174,0,204)` | bold |
| variable (label of a data directive) | `rgb(0,128,128)` | bold |
| error span | red | underlined |
| comment (from `;` to end of line) | `rgb(128,128,128)` | italic |

Order of application (later wins): default, mnemonic, registers, label definition on
this line, used labels, error span, comment.

Label/variable/constant coloring reflects the label's *current* kind, so lines that use
a label are re-highlighted when its kind changes.

### 6.4 Error line
Below the editor, a single-line red (`rgb(255,0,0)`) label. It shows:
- When the caret moves: the parse error of the caret's line, or empty.
- When a line is re-parsed and it is the caret's line: its error, or empty.
- When Step / Execute-current-line / Run hits a parse or runtime error: that message
  (Run also pauses). A successful Step clears it.
- Reset clears it.

### 6.5 Incremental parsing
Each edit marks the touched lines (and new lines) for re-parse; parsing then cascades:
- A line's "last label" is the label of the nearest preceding non-empty line, if that
  line is label-only. Parsing a line may first parse earlier pending lines.
- When a label definition changes kind (label/variable/constant) or appears/disappears,
  all lines that use it, and all lines currently in error, are re-parsed.
- A label defined on two lines: the later-parsed definition gets the error
  `Label already defined in line N` (N = 0-based line of the existing definition).
- A full re-parse happens on Reset.
The port can re-parse the whole document on each change (documents are small) as long
as the observable results match.

## 7. Registers panel

Titled box `Registers`.

### 7.1 Format toolbar
Four mutually exclusive toggles, each 45x27: `bin`, `±dec` (selected at start), `dec`,
`hex`. They set the display/edit radix of all register fields:

| Toggle | Display of a value `v` with size `n` bytes |
|---|---|
| bin | binary of `v` without leading zeros (`0` for zero) |
| ±dec | signed decimal (two's complement of `n` bytes) |
| dec | unsigned decimal |
| hex | `0x` + uppercase hex, zero-padded to `2n` digits |

### 7.2 Register rows
Nine rows in this order: EAX, EBX, ECX, EDX, ESI, EDI, ESP, EBP, EIP. Each row has a
small expand button on the left and two alternative views (one visible at a time):

- **Collapsed (default):** label `EAX: ` (35 px) and one text field with the full
  32-bit value (size 4 for formatting).
- **Expanded:** four text fields, one per byte, MSB first. Labels around them:
  - above byte 3: `EAX` (the 32-bit name);
  - above bytes 1-0 (shared shaded header): `AX` (16-bit name);
  - below byte 1: `AH`; below byte 0: `AL` (8-bit names, each on a tinted background).
  - For ESI/EDI/ESP/EBP only the 16-bit name (`SI`...) appears; no 8-bit names. For EIP
    no 16-bit or 8-bit name. Missing names leave the cell blank with neutral background.
- Expand button text in the original is `>` / `^` (inconsistent, 07 Q-UI-3). Port:
  `▸` collapsed, `▾` expanded.

Behavior:
- **Bold** = recently changed (04 §8): the collapsed field is bold if any part of the
  register changed in the last step; in the expanded view each byte field is bold if
  that part changed (byte 0 if AL/AX/EAX changed, byte 1 if AH/AX/EAX changed, bytes
  2-3 if EAX changed as a whole).
- **Editing:** pressing Enter or leaving a field parses its text in the current radix
  and writes it: the collapsed field writes the whole 32-bit register; a byte field
  replaces only that byte. Parsing: hex mode accepts with or without `0x`; bin mode
  accepts with or without trailing `b`; dec modes accept a decimal number; all modes
  also accept any literal form from 03 §3. Invalid input is ignored (field reverts on
  next refresh).
- **Highlight colors** (when the memory panel's `highlight` toggle is on): field
  backgrounds EAX `rgb(255,200,190)`, EBX `rgb(250,250,200)`, ECX `rgb(200,240,200)`,
  EDX `rgb(200,200,240)`, ESI `rgb(250,230,180)`, EDI `rgb(240,200,240)`; others and
  highlight-off white.

## 8. Flags

Below the register rows, a 4x2 grid of checkboxes in this order (row-major):
`Carry`, `Overflow`, `Sign`, `Zero`, `Parity`, `Auxiliary`, `Trap`, `Direction`.
They reflect CF, OF, SF, ZF, PF, AF, TF, DF after each refresh. Clicking a checkbox sets
that flag immediately.

## 9. FPU panel

Titled box `FPU Registers` containing a two-column table `name` | `value`, 8 rows:
- Row `i` (0..7) is physical register `R_i`. Its name is `ST<k>` with
  `k = (i - TOP) mod 8`. The row whose name is `ST0` is bold (all cells).
- `value` is the double in Java `Double.toString` format (`0.0`, `1.5`,
  `3.141592653589793`, `1.0E10`, `NaN`, `Infinity`). Empty registers still show their
  last value (tags are not displayed).
- `value` cells are editable: the text is parsed as a double and written to `R_i`;
  invalid text is ignored.
- The table is rebuilt on every refresh.

## 10. Memory panel

Titled box `Memory`; toolbar above a table.

### 10.1 Toolbar
| Control | Default | Tooltip | Effect |
|---|---|---|---|
| `desc` toggle | off | Show cells in descending order | Reverse row order (highest address first) |
| `hex` toggle | on | Show addresses as hex numbers | Address column as `0x` + uppercase hex (no padding) or decimal |
| `highlight` toggle | off | Highlight cells that registers are pointing to | Colors rows and register fields (7.2) |
| spacer | | | |
| `8 Bit` / `16Bit` / `32Bit` | `32Bit` | | Mutually exclusive cell width; also scrolls the table to the top |

### 10.2 Table
- Columns: `address`, `signed int`, `unsigned int`, `hex`.
- With width `w` bytes there are `memorySize / w` rows; row `r` covers addresses
  `start + r*w ... start + r*w + w - 1` (ascending), or the reverse row order with
  `desc`.
- `signed int` / `unsigned int`: the little-endian `w`-byte value at the row address.
  `hex`: `0x` + uppercase hex zero-padded to `2w` digits.
- **Editable:** the three value columns. The entered text is parsed (any literal form
  from 03 §3; in the `hex` column a missing `0x` is added) and written as `w` bytes
  little-endian to the row address. Invalid input is ignored.
- Rendering per row:
  - **bold** if any byte of the row changed in the last step (04 §8);
  - **stack** background `rgb(210,240,200)` if row address >= ESP;
  - with `highlight` on: if the row address equals the 32-bit value of EAX, EBX, ECX,
    EDX, ESI or EDI (first match in the order EAX, EBX, ECX, EDX, ESI, EDI, ESP, EBP,
    EIP; ESP/EBP/EIP have no color), the row gets that register's color (7.2),
    overriding the stack color.
- *Port note:* memory can be up to megabytes; use a virtualized table
  (e.g. Angular CDK virtual scroll).

## 11. Context help pane (bottom `Help` tab)

An HTML view that follows the caret: whenever the caret moves to a line, or the caret
line is re-parsed, it shows `help/en/<MNEMONIC>.htm` for that line's mnemonic. Lookups
are case-insensitive. If no page exists: text `No help found for <MNEMONIC>`. If the
line has no mnemonic (empty, label-only, comment, or the mnemonic is unknown): `No help
available for current context.` Pages are standalone HTML with inline styles (09 §1).

## 13. Dialogs

- **Open/Save code:** filter `Assembler Code (*.asm)`. **Save/Load memory:** filter
  `Memory and Register data (*.mem)`. The last used paths are remembered
  (`lastpath.asm`, `lastpath.mem`). *Port note:* use the File System Access API where
  available (gives real Save with a remembered handle) and fall back to
  `<input type=file>` plus a download for Save. Save Code writes back to the
  document's remembered file and shows the dialog only when there is none; Ctrl+Shift+S
  is Save Code As (09 §2).
- I/O exceptions show a modal message with the exception text. *Port note:* an in-app
  modal (Angular CDK dialog) headed `Message` with an `OK` button; the text is the
  error's `name: message`.
- Device modules use small prompt and choice dialogs (06). *Port note:* implement as
  Angular Material (or equivalent) dialogs with the same texts.
